# Try the project pilot

Bring one project you already work on with an AI agent. Keep its files where
they are. The pilot asks whether the folder helps you continue that work and
understand its changes; formal evaluation comes later.

1. Open this folder with your coding agent and say `hi`. Ask it to help finish
   one small piece of your real project. Approve the folder access it echoes.
2. At the end, read the EM line under the answer, then the brief update and the
   project's STATUS. You should be able to tell what changed, what remains and
   where the evidence lives.
   Inspect the changes and approve the commit when ready; you or the agent can run it.
3. On another day, open a fresh session and say “Continue this project.” See
   whether it recovers your decision and open questions without a long retelling.
4. Before an actual handoff, ask “Check what we decided against what exists.”
   An explain-back is optional; you can decline it and continue working.

If something helps or frustrates you, use [FEEDBACK.md](FEEDBACK.md). One
specific incident is enough. There is no questionnaire schedule or automatic
log upload. Recruitment and follow-up are handled by the person who invited you.

Current system state: [STATUS.md](STATUS.md). Session history:
[UPDATES.md](UPDATES.md). Version history: [CHANGELOG.md](CHANGELOG.md).

## Working with several agents

You may run two agents together for planning or research, each saving a separate
report. Pause both passes before one agent implements, tests or integrates the
results. This applies across project scopes too. The current sole worker keeps
the shared project state up to date; no permanent integrator is needed.
You settle disagreements about intent. Pending reports remain available.
The assistant follows [the coordination procedure](kb/coordination.md).
